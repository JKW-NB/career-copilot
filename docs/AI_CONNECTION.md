# 桌面模型连接

## 使用

在“设置与数据”填写基础地址、默认模型、高质量模型及自己的 Key。基础地址应是提供方公布的兼容 Chat Completions 地址前缀，程序追加 /chat/completions；需要支持 response_format: json_object。默认模型用于助手和连接检查，高质量模型用于岗位分析，可填同一个 ID。不会自动选择价格、购买额度或替用户创建账户。

保存只更新设置和 Windows 凭据，不发请求。“测试连接”只发送固定测试问题。远程要求 HTTPS，本机回环允许 HTTP；禁止带用户名、密码、查询参数的 URL 和自动重定向。换基础地址需要为新地址单独保存 Key，旧 Key 不会自动带过去；删除操作仅删除当前地址凭据。迁移到另一台设备后应重新配置凭据。

## 明确选择再发送

侧栏底部开关展开右侧面板，主页面保留。面板显示当前页面和接口地址，可选择岗位、是否发送 JD、至多 20 条当前事实，以及一个可选事实修改目标；目标事实自动纳入所选上下文。最近两轮对话默认不附带。发送前可以展开查看内容，只有点击发送才调用模型。岗位分析只发所选 JD 和本次问题；切回一般问答不会自动携带 JD。

不会自动附带整份资产描述、联系人、教育背景、文件或 PDF。用户手工输入或勾选的文本可能包含个人资料，应以面板预览为准。仅收起保留本次运行内的会话；程序重启不恢复完整问答。

## 提案与历史

普通回答不提供写入按钮。岗位分析和指定事实改写展示原目标及预览，必须点击“应用修改”才进入受信任业务命令：

- 岗位要求保存为新版本；若已有后续分析或 JD 变化则拒绝旧建议。未保存的手工要求也必须先处理。
- 事实改写创建 UNCERTAIN 修订，保留原 Ownership，不能自动升级为用户确认或证据验证。重新审查后才能用于新组合或新简历。
- 应用与提案状态处于同一 SQLite 事务。重复点击返回已应用结果，过期或已放弃提案不能写入。
- 既有 Confirmed Portfolio、Ready 简历、Final 和投递绑定不随改写变化。当前个人版没有直接改写历史 Bullet 或单步撤销入口，可通过新的手工事实修订修正。

Schema V3 的 ai_runs 只保存运行类型、模型、输入摘要、状态及经过校验的最小提案/目标；不保存原始 Prompt、完整上下文或 Key。提案本身可能含用户选择资料的改写，保留在本地；“暂不应用”清除数据库中的提案正文与目标。普通运行记录没有独立聊天数据库。

## 错误与验证边界

单次请求超时 45 秒、连接超时 10 秒；最多两次尝试。网络发送失败、429、5xx 或输出结构无效可能重试一次，401/403 不自动重试。读取响应上限 1 MiB。界面只显示脱敏错误，不回显服务响应或 Key。失败不会改写正式数据。

结构校验能拒绝类型、字段和长度错误，不能证明模型文字的真实性。事实改写始终重新进入待审查，简历编译继续采用用户确认的事实原文。实际外部模型效果须配置后单独验证；自动测试只使用合成数据、本机 HTTP 服务和独立 Windows 测试凭据，不访问用户真实资料或付费模型。

验证命令：npm run check、npm run check:rust、桌面构建后 npm run test:desktop:ai。该桌面流程覆盖保存不联网、无个人资料连接测试、岗位提案预览与未保存编辑保护、明确应用、事实放弃/应用、历史保留、面板会话保留、密钥删除及重启持久化。
