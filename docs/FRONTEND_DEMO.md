# DEMO-T1 — 前端交互预演

JKai 已确认先做前端 Demo，再完成桌面初始化与真实业务。此任务插入 M0-T1 之前，不把模拟行为计作 M1–M7 完成。

## 目标与设计

一个合成岗位、五项合成职业贡献、一条可操作流程：Strategy → Contributions → Resume → Final。Career Assets 可浏览事实/证据；Home、Library、Settings 为简化入口。默认进入岗位 Strategy，让用户先看到岗位结论和证明责任，Context Panel 解释当前选择。暖白工作区、森林绿导航、橙色动作与细线表格，避免总分、花哨图表和密集审批。

全部页面标示演示模式；固定场景模拟推荐和改写，不调用模型、不上传用户文件、不接数据库或真实投递。状态存在内存中，刷新/重置恢复示例。Final 使用虚拟文件记录，明确不创建真实 PDF 或投递。

## 必须可操作

- Strategy：四项证明责任、支持贡献、JD 原文、Gap 与解释；进入组合。
- Contributions：添加/移除/替换、Core/Supporting/Reserve、选择计划事实、覆盖随选材变化；未使用不确定事实不阻塞，已选高风险未确认事实阻塞；取消该事实后可确认快照。
- Resume：由确认组合生成，局部预设改写、编辑审查、同贡献事实切换、Pinned、复制预览、内容 Ready。演示检查采用保守规则：任意非预设编辑进入 Review，不宣称具备通用语义识别；新数字不会静默保存。
- 上游变更：确认新组合后提示受影响内容，用户选择局部更新；其他改写/固定事实保留；旧 Ready 快照保留。
- Final：从 Ready 内容保存虚拟文件样例、模拟投递后冻结、归档后仍锁定。Library 查看已保存内容/样例记录。
- 资产：搜索、浏览贡献及事实来源、展示可信/风险状态。暂不提供虚假的真实导入功能。

## 最小实现边界

React + TypeScript + Vite；`src/demo/fixtures.ts` 合成数据，`src/application/demo-service.ts` 内存用例与规则，`src/app/` 组合与页面，CSS 设计 tokens。UI 通过服务动作变更业务状态，不直接操作数据存储；未来生产服务替换演示服务，不把 mock 当真实 AI。

## 执行步骤与验收

1. 建立前端配置、锁文件、测试入口，保留现有文档验证。
2. 先写服务行为测试：覆盖损失、高风险阻塞、确认快照不可变、改数字待审、局部更新保留未影响内容、Pinned、样例使用锁。
3. 实现服务、页面及响应式布局，确保键盘焦点/模态框可关闭、窄屏能操作。
4. 运行文档测试、Vitest、类型检查、构建；浏览器端实际验证主流程、拒绝路径和移动端布局，截图检查。
5. 同步四文档的实现状态，保留 M0-T1 待执行，记录验证结果并提交独立 commit。
