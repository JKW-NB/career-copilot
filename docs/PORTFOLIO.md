# Career Copilot — 作品集项目说明

## 项目要解决的问题

求职者常把经历散落在旧简历、项目记录和文档中。为不同岗位反复改写时，容易夸大职责、混淆团队与个人成果，也难以追溯某次投递究竟使用了哪份内容。

Career Copilot 的主线是：职业事实 → 岗位要求 → 事实组合 → 简历快照 → 最终 PDF → 投递记录。它把经历材料、可使用事实与最后提交文件分开管理。

## 当前可验证的能力

个人桌面工作区从空数据开始，手工记录真实经历、审查事实、为岗位选择事实、生成保留来源引用的内容版本。排版稿可导出为 HTML 或 Markdown；用户在外部完成排版后，登记真实 PDF 并创建投递记录。应用不会自动向招聘平台发送申请。

内容不会因为上游事实修订或撤回而静默改变；新的编译则必须重新检查事实是否有效。登记投递前重新校验文件摘要，登记后即使记录作废仍保留永久文件锁。

## 产品与工程取舍

- **先事实，后表达**：第一版内容直接使用已确认事实，宁可表达朴素，也不把无法核实的改写视为可信。
- **本地优先**：Tauri + React + TypeScript，Rust 命令执行最终校验，SQLite 保存关系与版本，文件系统保存 PDF。
- **演示隔离**：合成 Demo 保留丰富的交互演示；个人数据进入另一套真实业务命令，避免让演示状态冒充产品能力。
- **可追溯交付**：确认组合、Ready 内容和最终文件形成明确的版本绑定，投递记录引用具体 PDF。
- **小步落地**：当前迁移只实现手工闭环需要的领域子集；不把蓝图中的 31 表和 53 个 Task 宣称全部完成。

## 3–5 分钟演示路线

1. 新增“校园用户研究”资产，描述背景。
2. 录入一条具体事实；涉及数字时显示额外审查，明确用户确认不等于证据验证。
3. 新增目标岗位，录入核心能力要求。
4. 选择已确认事实并确认组合，生成一份内容版本。
5. 导出 HTML 排版稿，展示来源一致的内容；登记最终 PDF，记录一次已经实际完成的投递。
6. 修订原事实，展示历史简历没有改变，新编译需要重新确认。
7. 关闭并重新启动，展示职业资产、内容和投递记录仍在。

使用合成材料录制公开演示；不要上传个人联系方式或私有证据。视频或截图中，真实个人工作区与 AI 交互 Demo 应明确区分。

## 后续里程碑

外部 AI 连接需明确用户选择的接口与发送内容后接入；届时加入系统凭据、结构化提案、显式应用与失败恢复。之后补充文件解析、访谈补全、能力分析、方向母版和组合优化。当前不提供真实 AI 效果、用户规模或业务提升数据，未做过的验证不写成成果。

## 可用于简历的项目描述（按实际完成情况选择）

- 设计并实现本地求职工作区，打通职业事实审查、岗位组合、简历版本、最终 PDF 与投递记录链路。
- 通过 Rust 受信任命令集中执行业务校验，使用 SQLite 事务、追加修订和不可变快照保护历史内容。
- 实现最终文件摘要校验与永久使用锁，并通过服务合同、浏览器流程及真实桌面重启测试验证核心链路。

不要在个人简历中写“已完成全套 AI 求职系统”或填写尚未测量的效率提升百分比。
